Context Files (Always-On Routing)

CLAUDE.md

Project instructions. Defines the agent team, routing table, active skills, and work loop. Read by Claude Code at every session start. Each client project gets its own copy from templates/project-scaffold/CLAUDE.md.

~/.claude/rules/agent-routing.md

Global routing rules. Maps trigger phrases → agents + skills. Hard rules (no dev without plan, no publisher push, no email without approval). Deployed to all client machines via infiniteleverage-patch.

~/.claude/rules/global-engineering.md

Engineering guardrails. Git discipline, deployment constraints (git push only), secrets handling, Supabase rules. Always active — cannot be overridden by operator instructions.

Hard Rules
No dev without an approved plan Developer never starts implementation without a PM-approved plan. Route to PM first.
No publish without approved content + image Web Publisher requires Writer approval AND Designer image before building any page.
No email send without operator approval Email Marketer always drafts first. Operator explicitly approves before any send.
No direct deploy — git push only DevOps never uses vercel deploy or direct CLI. All deployments via git push → CI/CD.
QA always triages before routing Every bug is classified, scored (severity × frequency × blast radius), and assigned before work starts.
No agent merges its own PR Developer opens PR → QA verifies → Operator or PM merges. No exceptions.
DevOps escalates to human engineer When infra issues exceed defined scope, DevOps stops and notifies a human engineer. [P12]
Designer waits for approved copy No images generated until the Writer's content is signed off by the operator.
